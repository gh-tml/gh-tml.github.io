# 教学文章写作指南

这篇文章是当前项目给新贡献者的默认入口。

从现在开始，默认主线只收敛到两件事：

1. 会在本地仓库里写 Markdown 教程，并用本地静态服务器预览。
2. 需要动画时，再学 `使用网页特殊动画模块.md` 这一篇。

也就是说：不会 C#、不了解 `ContentProjects`，都不会阻止你先把文章写出来并完成预览。

## 先记住当前主线

请把学习顺序压缩成下面两步：

1. 先学本篇，把文章写出来。
2. 再学 `使用网页特殊动画模块.md`，决定是否给文章加 `anim.ts` 动画。

下面这些内容先不算新人必学：

1. `ContentProjects` 本地工程
2. FX / Shader 编写
3. 本地桥接服务
4. 复杂 C# 示例维护

它们仍然有用，但应该放到“已经能正常写文并提交”之后。

## 你要交付的最小结果

一篇真正可进入评审的文章，最低满足下面 7 条：

1. 路径位于 `site/content/<分类>/` 下。
2. 有 YAML Front Matter，至少包含 `title` 与 `description`。
3. 正文至少能让读者看懂“目标、示例、小结”。
4. 本地预览正常，没有明显断链或占位词。
5. 执行 `npm run build`，把生成的 `site/content/config.json`、`site/assets/search-index.json`、`site/sitemap.xml` 等文件一起提交。
6. 再执行 `npm run check-generated`，确认没有漏提生成物，PR 不会因为脏产物失败。
7. 用 `git commit` 提交到分支并开 PR，描述里写清改了什么、为什么改、怎么验证。

如果你现在只能完成前 4 条，已经足够做出一份可预览草稿；但还不能把它当成“已经可 review”。

## 第一步：准备本地仓库

```bash
git clone https://github.com/DPapyru/DPapyru.github.io
cd DPapyru.github.io
npm ci
python -m http.server 8000
```

打开 `http://localhost:8000/site/` 就能看到站点。

认三个位置就够：

1. `site/content/`：所有文章，按分类放。
2. `site/pages/viewer.html`：单篇文章的阅读页，用 `?file=分类/文件名.md` 打开。
3. 终端：跑 `npm run build` 刷新索引与搜索。

## 第二步：新建一篇 Markdown 文章

推荐操作：

1. 在 `site/content/` 下选一个分类目录，例如 `如何贡献`。
2. 新建 `你的名字-文章标题.md`。
3. 先写 front matter，再写正文。

文件名尽量用英文或数字，别带空格和特殊符号。

## 第三步：先把 Front Matter 补齐

最小模板如下：

```yaml
---
title: 文章标题
description: 一句话说明本文解决什么问题
topic: article-contribution
---
```

对新人来说，先把这三个字段写对最重要：

1. `title`：给读者看的标题。
2. `description`：一句话交代本文解决什么问题。
3. `topic`：当前贡献文档统一使用 `article-contribution`。

如果你愿意再补充一点信息，可以继续加：

```yaml
author: 你的名字
difficulty: beginner
time: 15分钟
```

键名不用背，抄上面的模板改值就行。

## 第四步：正文只先学最常用的 Markdown

先掌握下面 6 种就够写大多数教程：

1. 二级标题：`## 小节标题`
2. 列表：`1.` 或 `-`
3. 代码块：三反引号包起来
4. 普通链接：`[说明](./另一篇.md)`
5. 图片：`![说明](../../assets/imgs/example.png)`
6. 提示框：

```text
> [!NOTE]
> 这里写提醒内容
```

写作时有一个很实用的经验：先把正文组织成固定 4 段。

1. 这章要解决什么问题
2. 最小示例是什么
3. 每一步在做什么
4. 学完以后下一步看什么

这样写出来的文章，对新人最友好，也最方便 reviewer 快速检查结构。

## 第五步：边写边预览，不要等到最后

本地起静态服务器，然后用 viewer 打开你的文章：

```text
http://localhost:8000/site/pages/viewer.html?file=如何贡献/你的名字-文章标题.md
```

注意两点：

1. 新建的文章要先跑一次 `npm run build`（或 `npm run generate-index`）才会进索引，否则 viewer 会提示“文档不存在或未被索引”。
2. 预览的是真实渲染结果：嵌入、提示框、代码高亮都和线上一致。

## 第六步：提交 PR

```bash
git checkout -b docs/your-topic
git add site/content site/assets/search-index.json site/sitemap.xml site/assets/semantic
git commit -m "docs: 补充某主题入门教程"
git push -u origin docs/your-topic
```

然后在 GitHub 上开 PR，描述里写清：改了什么、为什么改、怎么验证。

注意：`config.json`、`search-index.json`、`sitemap.xml`、`semantic/*.json` 都是构建产物，必须和文章一起提交，否则 CI 的 `check-generated` 会失败。

## 写给第一次贡献的人

如果你担心“我不会编程，能不能先写文”，答案是：可以。

在当前项目里，优先级是这样的：

1. 先把教程写清楚。
2. 再决定是否需要代码片段。
3. 最后才是动画、Shader、本地工程这些增强能力。

不要一开始就把自己卡在工具链上。

## 附录：提交前的本地检查

只要准备把 PR 送进评审，就必须在本地跑这两条验证：

```bash
npm run build
npm run check-generated
```

用途分别是：

1. `build`：刷新结构索引、搜索索引、动画产物和站点构建结果，并产出 PR 里必须一并提交的生成文件。
2. `check-generated`：模拟 CI，检查生成文件是否与源码一致，避免 PR 因“少提了生成物”直接失败。

补充说明：仓库里仍有部分历史内容未完全整理；如果你额外运行 `npm run check-content`，看到与自己这次改动无关的旧报错，请在 PR 描述里注明，不必误判成“自己这篇写坏了”。

## 下一步

如果你的文章需要演示运动、交互或可视化过程，继续阅读：`使用网页特殊动画模块.md`。

如果你只是来补一篇普通教程，到这里就已经够用了。
